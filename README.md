# 한국 MCP 서버 순위 (mcp-rank)

한국 서비스에 붙는 MCP(Model Context Protocol) 서버를 GitHub API 값만으로 줄 세우고,
매일 스냅샷을 쌓아 순위 변동을 보여주는 정적 사이트.

**사이트:** https://gigaminkyu.github.io/mcp-rank/

## 왜

한국 MCP 서버는 흩어져 있고, 어느 게 살아 있는지 알려면 하나씩 열어봐야 한다.
목록은 이미 있다 — 없는 건 "지금도 관리되고 있나"에 대한 답이다.

## 점수는 사람 손을 안 탄다

| 항목 | 만점 | 계산 |
| --- | --- | --- |
| 인기 | 40 | 10 × log₁₀(별+1), 40에서 자름 |
| 관리 | 30 | 마지막 커밋 30일 이내 30 / 90일 20 / 180일 12 / 1년 5 / 그 이상 0 |
| 문서 | 20 | README 8000자↑ 20 / 3000자↑ 14 / 1000자↑ 8 / 그 외 3 |
| 신뢰 | 10 | 라이선스 5 + 릴리스 존재 5 |

코드 품질·도구 개수·실제 동작 여부는 **일부러 뺐다.** 자동으로 확인할 방법이 없는 걸
점수에 섞으면 순위가 의견이 된다. 별 수가 곧 품질이 아니라는 것도 그대로 남겨뒀다 —
로그를 씌운 이유가 그거다.

## 후보를 어디서 모으나

두 갈래다.

1. [darjeeling/awesome-mcp-korea](https://github.com/darjeeling/awesome-mcp-korea) 목록
2. GitHub 검색 직접 훑기

남의 목록 한 장에만 기대면 그쪽이 멈추는 순간 이 순위도 같이 멈춘다.
검색 결과를 다 넣지도 않는다 — 이름에 `mcp` 가 있거나 `mcp-server` 토픽이 달렸거나
설명이 스스로 MCP 서버라고 말하는 것만 남긴다. 한국 여부도 토픽이 아니라 이름·설명에서만
본다(번역기가 지원 언어로 달아둔 `korean` 토픽은 근거가 못 된다).

## 순위 변동

매일 06:00 KST에 GitHub Actions가 그날의 순위·별·점수를 `history/` 에 한 파일로 남긴다.
▲▼ 는 어제 파일 대비, 별 증가량은 일주일 전 파일 대비다. GitHub이 과거 별 기록을 안 열어주므로
소급 생성이 불가능하다 — **안 돌린 날은 영구히 빈칸이다.** 그래서 실패하면 조용히 넘어가지 않고
워크플로를 빨갛게 남긴다.

## 구성

- `collect.py` — 후보 수집 + GitHub API 조회 → `data.json`
- `build.py` — `data.json` → `docs/` 정적 사이트
- `history/` — 일별 스냅샷
- `.github/workflows/update.yml` — 매일 갱신
